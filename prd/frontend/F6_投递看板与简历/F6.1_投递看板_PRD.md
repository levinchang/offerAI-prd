# F6.1 投递看板

| 项目 | 说明 |
|------|------|
| **功能名称** | 投递看板视图 |
| **对应 FeatureList** | 6.1.1 阶段看板、6.1.2 列表视图 |
| **对应 ER 实体** | 投递记录 |
| **对应时序图** | 无 |

---

## 1. 需求背景与目标

- 会员用户需要以「阶段」维度管理投递进度，核心为 Kanban 看板；同时支持列表视图便于批量查看与筛选。
- 目标：看板多列对应阶段（已收藏→已投递→笔试→一面→二面/终面→OC→已拒/放弃）；支持看板/列表双视图切换；卡片或行展示公司、岗位、来源、投递日期、阶段、关联简历、备注等；列表视图支持排序与筛选（含分组筛选，见 F6.3）。

---

## 2. 角色与入口

- **角色**：已登录会员（校招或事业编会员均可使用投递看板，与岗位来源无关）。
- **入口**：顶部导航「投递看板」；未登录不展示该入口或点击后先弹登录。
- **权限**：投递看板为会员能力，与 F1.3、后台会员体系一致。

---

## 3. 页面结构与交互

### 3.1 看板视图（Must）

- **布局**：横向多列，每列对应一阶段。阶段列：**已收藏** → **已投递** → **笔试** → **一面** → **二面/终面** → **OC** → **已拒/放弃**。列内为卡片列表，每卡展示：公司名、岗位、来源（校招表/事业编表/手动）、投递日期、关联简历（若有）、简短备注（若有）。
- **交互**：点击卡片可展开详情或进入编辑（阶段变更、备注，见 F6.2）；**拖动卡片**到另一列即更新阶段（若产品支持拖拽）；或卡片上提供阶段下拉快速变更。新增记录见 F6.2。
- **空状态**：某列无记录时展示「暂无」或引导「从信息表标记投递」/「手动新增」。

### 3.2 列表视图（Should）

- **布局**：表格形式，列：公司、岗位、来源、投递日期、阶段、关联简历、备注、操作（编辑、删除等）。支持按阶段、来源、分组（F6.3）、时间排序与筛选。
- **交互**：行内「编辑」进入编辑抽屉/弹窗（F6.2）；支持切换回看板视图。

### 3.3 视图切换

- **切换入口**：页面上方或顶栏提供「看板」「列表」切换 Tab 或按钮；当前视图状态可记忆（如 localStorage）。

---

## 4. 字段规格表（展示）

| 字段显示名 | 字段键名 | 所在区域 | 类型 | 说明 |
|------------|----------|----------|------|------|
| 公司 | company | 卡片/列表 | string | — |
| 岗位 | job_title | 卡片/列表 | string | — |
| 来源 | source | 卡片/列表 | enum | 校招表/事业编表/手动 |
| 投递日期 | apply_date | 卡片/列表 | date | — |
| 阶段 | stage | 卡片/列表 | enum | 已收藏～已拒/放弃 |
| 关联简历 | resume_name | 卡片/列表 | string | 见 F6.4、F6.5 |
| 备注 | remark | 卡片/列表 | string | 简短展示，完整见 F6.2 |
| 分组 | group_ids | 列表筛选 | array | 见 F6.3 |

---

## 5. 业务逻辑与状态流转

- **R-01**：看板列与阶段枚举一致；一条记录仅属于一个阶段，拖动或下拉变更后调用更新接口（F6.2）。
- **R-02**：校招与事业编投递记录在同一看板展示，通过「来源」或标签区分；阶段枚举可统一（已投递/笔试/一面/二面/OC/已拒）或事业编侧用「已报名/笔试/面试/录用/未过」映射到同一看板列。
- **R-03**：仅展示当前用户的投递记录；删除为软删除或移至「已拒/放弃」由产品定。

---

## 6. 异常与边界

- 未登录/非会员访问：引导登录或开通会员。
- 无记录：看板与列表均展示空状态与引导文案。

---

## 7. 依赖与待定项

- **依赖**：投递记录列表/看板数据接口（F6.2）；分组筛选依赖 F6.3；简历名称展示依赖 F6.4/F6.5。
- **待定**：是否支持看板列自定义（如隐藏某列、调整顺序），V1 可固定列。
