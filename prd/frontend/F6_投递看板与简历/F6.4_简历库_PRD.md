# F6.4 简历库

| 项目 | 说明 |
|------|------|
| **功能名称** | 简历上传、管理与删除/替换 |
| **对应 FeatureList** | 6.4.1 上传简历、6.4.2 删除/替换 |
| **对应 ER 实体** | 用户简历（简历库） |
| **对应时序图** | 无 |

---

## 1. 需求背景与目标

- 会员需上传多份简历（如不同方向），在投递时选择关联简历版本；简历库独立于投递看板，属于「简历管理」需求。
- 目标：支持 PDF/Word 上传，单文件 ≤10MB，最多 5 份；支持自定义命名（如「互联网-产品岗」）；支持删除与替换；删除后投递记录中关联该简历的显示「已删除」而不影响记录存在。

---

## 2. 角色与入口

- **角色**：已登录会员。
- **入口**：个人中心「简历库」入口，或投递看板「简历管理」/「我的简历」；也可在编辑投递记录时从「关联简历」下拉进入「管理简历」跳转简历库。简历库为独立页面或抽屉。

---

## 3. 页面结构与交互

### 3.1 上传简历

- **入口**：简历库页「上传简历」按钮。
- **交互**：选择本地文件（PDF 或 Word），可选填写「简历名称」（默认取文件名）；校验：格式、大小 ≤10MB、当前简历数量 <5。上传成功后列表新增一条，展示名称、上传时间、文件大小、操作（重命名、删除、替换）。
- **命名**：支持上传后「重命名」，便于区分版本（如「互联网-产品岗」「国企-通用」）。

### 3.2 删除与替换

- **删除**：行内「删除」→ 二次确认；删除后该简历从列表移除，已关联该简历的投递记录在「关联简历」列显示「已删除」或占位，不删除投递记录本身。
- **替换**：行内「替换」→ 重新选择文件，覆盖原文件，保留同一简历 ID 与名称（或名称可改）；替换后原链接失效，投递记录仍关联该 ID，展示为新文件内容（若后端按 ID 返回最新文件）。

---

## 5. 业务逻辑与状态流转

- **R-01**：单用户最多 5 份简历；超过时上传入口置灰或提示「已达上限，请删除后再上传」。
- **R-02**：文件存储由后端与 OSS 等方案决定；前端仅上传与展示列表，不直接展示文件内容（预览可选）。
- **R-03**：删除为物理删除或软删除由后端定；软删除时投递记录关联展示「已删除」并不可再选该简历。

---

## 6. 异常与边界

- 格式错误：仅允许 PDF/Word，其他格式提示「请上传 PDF 或 Word 文件」。
- 超大小：提示「文件不超过 10MB」。
- 上传失败：提示「上传失败，请重试」。

---

## 7. 依赖与待定项

- **依赖**：简历上传、列表、重命名、删除、替换接口；存储与访问控制由后端实现。
- **待定**：是否支持简历预览（在线查看），V1 可不做；替换是否保留历史版本，V1 不保留。
