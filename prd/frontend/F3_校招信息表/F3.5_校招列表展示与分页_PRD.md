# F3.5 校招列表展示与分页

| 项目 | 说明 |
|------|------|
| **功能名称** | 校招岗位表格展示与分页 |
| **对应 FeatureList** | 3.1.1 列表展示、3.1.2 截止日期高亮 |
| **对应 ER 实体** | 校招岗位 |
| **用户故事** | 作为求职者，我希望在筛选后以表格形式浏览校招岗位列表，看到更新时间、公司、岗位、城市、网申时间等关键信息，并能分页查看；临近或已截止的岗位有视觉区分。 |

---

## 1. 验收标准（可闭环测试）

- [ ] **AC1** 列表以表格展示，列顺序：**更新时间、公司名称、岗位、工作城市、行业、信息来源（如「官方公众号」+ 超链接「公告原文」）、网申时间、招聘范围、投递链接（点击投递/邮箱投递）、操作专区（标记进度、编辑备注）**；列行为与权限见 F3.6。
- [ ] **AC2** 公司名称列可展示企业类型标签（如国企、民企、事业单位等），样式与设计规范一致。
- [ ] **AC3** 支持分页：每页条数（如 20/50）、总数与页码；切换页码或每页条数后刷新列表。
- [ ] **AC4** 网申截止 ≤3 天时该行或该单元格红色高亮；已截止行或单元格置灰（Should）。
- [ ] **AC5** 无数据时展示空状态「暂无岗位信息」；搜索/筛选无结果时提示「未找到相关岗位，请调整筛选条件」。
- [ ] **AC6** 列表默认按更新时间倒序；投递链接与会员操作区仅负责展示与点击行为，具体权限与操作见 F3.6。

---

## 2. 角色与入口

- **角色**：所有访问校招表页的用户；行内操作（投递、收藏等）的可见与可点击依赖登录与会员态，见 F3.6。
- **入口**：校招表页，筛选区下方；数据受 F3.3 筛选、F3.4 分组、F3.7 收藏/进度筛选影响。
- **数据范围**：仅展示已上架、未删除的校招岗位。

---

## 3. 页面与字段

### 3.1 表格列

| 列名 | 字段/说明 | 展示说明 |
|------|-----------|----------|
| 更新时间 | updated_at | 日期或日期时间，倒序 |
| 公司名称 | company_name + company_type | 名称 + 企业类型标签（国企/民企等） |
| 岗位 | job_title | **多值**：一个岗位可能招多个职位，展示为「岗位A、岗位B」；存储见 4.2 |
| 工作城市 | city | **多值**：工作地点可能多个，展示为「城市A、城市B」；存储见 4.2 |
| 行业 | industry | 文本，与筛选「行业」一致 |
| 信息来源 | source_name + original_url | 如「官方公众号」+ 超链接「公告原文」；未登录/未开会员点击链接→登录或开通，见 F3.6 |
| 网申时间 | apply_start_at～apply_end_at | 区间或「尽快投递」等文案 |
| 招聘范围 | recruit_scope | **多值**：可能面向 26届、27届等，展示为「26届、27届」；存储见 4.2 |
| 投递链接 | apply_url / apply_type | 「点击投递」或「邮箱投递」等，仅跳转第三方，不写入投递记录；未登录/未开会员点击→登录或开通，见 F3.6 |
| 操作专区 | — | 标记进度（下拉）+ 编辑备注；投递记录由用户在此标记产生，见 F3.6 |

- 投递链接仅用于跳转第三方官网/邮箱，**不**自动写入投递记录；用户需在**操作专区**内「标记进度」来管理与个人中心的投递信息。

### 3.2 截止高亮（Should）

- 网申截止日期距离当天 ≤3 天：该行或网申时间单元格红色高亮。
- 已截止（apply_end_at &lt; 当天）：该行或单元格置灰。
- 具体样式与是否做行级/单元格级由 UI 定。

### 3.3 分页

- 组件：页码 + 每页条数选择（如 20/50）+ 总条数展示。
- 行为：切换页码或每页条数时保留当前筛选与搜索条件，重新请求列表并刷新表格。

### 3.4 空状态与无结果

- 列表无数据（如无筛选条件时无上架岗位）：表格区展示「暂无岗位信息」。
- 有筛选/搜索但无结果：展示「未找到相关岗位，请调整筛选条件」。

## 4. 字段规格表（列表）

| 字段显示名 | 字段键名 | 类型 | 说明 |
|------------|----------|------|------|
| 更新时间 | updated_at | datetime | 倒序 |
| 公司名称 | company_name | string | 可模糊搜索 |
| 企业类型 | company_type | enum | 标签展示 |
| 岗位 | job_title | **多值** | 可模糊搜索；存储为数组或关联表，见 4.2 |
| 工作城市 | city | **多值** | 多选筛选；存储为数组或关联表，见 4.2 |
| 行业 | industry | string | 多选筛选 |
| 信息来源 | source_name, original_url | string + url | 展示名 + 公告原文超链接 |
| 网申时间 | apply_start_at, apply_end_at | date | 区间展示 |
| 招聘范围 | recruit_scope | **多值** | 26届、25届、27届等；存储为数组或关联表，见 4.2 |

### 4.2 多值字段存储说明（工作城市、岗位、招聘范围）

- **工作城市**、**岗位**、**招聘范围** 在业务上可能为一对多（一个校招岗位对应多个城市/多个职位名/多个届别），存储结构需支持多值。
- **建议**：  
  - 方案 A：主表存 JSON 数组或逗号分隔字符串，列表/筛选时解析；  
  - 方案 B：主表存主键，明细表存 岗位-城市-招聘范围 多对多关联，查询时 JOIN 或 IN。  
- 列表展示时用「、」或「,」连接多值；筛选时多选条件与多值字段做交集或包含判断，由后端约定。
| 投递链接 | apply_url, apply_type | url + enum | 点击投递/邮箱投递，仅跳转 |
| 操作专区 | — | — | 标记进度、编辑备注，见 F3.6 |

---

## 5. 业务规则

- **R-01** 列表仅返回 publish_status=已上架、lifecycle≠已删除；对非校招会员不返回真实投递/原文 URL（见 F3.6）。
- **R-02** 默认排序为更新时间倒序；分页参数与筛选条件一并传给列表接口。

---

## 6. 异常与边界

- 接口超时或失败：表格区提示「加载失败，请重试」并可重试。
- 数据量过大时依赖后端分页，前端不一次性拉全量。

---

## 7. 依赖与待定项

- **依赖**：校招列表接口（含筛选、分页、排序）；F3.3 筛选、F3.4 分组、F3.7 收藏/进度与列表联动；操作列行为见 F3.6。
- **待定**：是否有独立岗位详情页（当前可为行内「详情」链接或展开）。
