# F1.1 微信扫码登录与手机号登录

| 项目 | 说明 |
|------|------|
| **功能名称** | 微信扫码登录、手机号短信登录（可选）、账号绑定展示 |
| **对应 FeatureList** | 1.1.1 展示扫码弹窗、1.1.2 扫码自动注册/登录、1.1.3 登录态保持；手机号登录与绑定 |
| **对应 ER 实体** | 用户（前台 C 端用户，与管理员分离） |
| **对应时序图** | 时序图01_微信扫码登录（若有） |

---

## 1. 需求背景与目标

- 前台用户通过微信扫码完成注册/登录，无需账号密码，降低门槛、便于从小红书等渠道承接；同时支持手机号短信登录作为补充方式。
- 目标：登录页**默认**为「微信扫码登录」，可切换为「手机号短信登录」；扫码或短信验证通过后自动注册/登录，拉取微信头像与昵称（或手机号），创建 JWT；登录态 7 天内跨页面保持；账号设置页展示手机号/微信号绑定状态，支持绑定/更换手机号、解除绑定微信号（若产品支持）。

---

## 2. 角色与入口

- **角色**：访客、注册用户、会员用户（登录后区分）。
- **入口**：顶部导航「求职者登录」、或任意需登录操作（如收藏、工作台、购买等）时触发登录弹窗；**账号设置**在工作台内（头像下拉 → 账号设置），可进行手机号绑定/更换。
- **登录态**：Token 存前端（如 localStorage），请求头携带；过期或未携带时接口返回 401，前端跳转或弹出登录弹窗。

---

## 3. 页面结构与交互

### 3.1 登录弹窗

- **布局**：弹窗（居中、蒙层），非整页。扁平化风格：白底、清晰边框、主按钮红色。
- **Tab 切换**：顶部提供「微信扫码登录」「手机号短信登录」两个 Tab；**默认展示「微信扫码登录」**；切换后展示对应内容区。
- **微信扫码区**（默认）：
  - 标题：「微信扫码登录」或「登录后继续」。
  - 中部：二维码展示区（由后端或前端拉取临时 ticket 生成微信登录二维码）。
  - 说明文案：「请使用微信扫描二维码登录」；可选「扫码后自动注册/登录」。
  - 底部：取消/关闭按钮（灰色边框），主操作可为「刷新二维码」。
- **手机号短信区**（切换后）：
  - 手机号输入框、验证码输入框、「发送验证码」按钮（含倒计时与防重复）、「登录」主按钮。
  - 未注册手机号首次验证通过时自动注册并登录；已注册则直接登录。
- **交互**：
  - I-01：用户点击「求职者登录」或需登录操作 → 弹出登录弹窗（默认微信 Tab）；若已登录则直接进入目标能力或工作台。
  - I-02：微信扫码并在微信内确认 → 后端回调完成注册/登录，返回 JWT 与用户信息；前端关闭弹窗、更新导航栏状态、继续原操作或跳转。
  - I-02b：手机号 + 验证码填写后点击「登录」→ 后端校验验证码，通过则注册/登录并返回 JWT；前端同上。
  - I-03：二维码过期 → 展示「二维码已过期，请点击刷新」；提供「刷新二维码」按钮。
  - I-04：关闭弹窗 → 不执行登录，停留在当前页。
  - I-05：从账号设置内「绑定/更换手机号」打开登录弹窗时，可自动切到「手机号短信登录」Tab，便于用户完成绑定。

### 3.2 账号设置页（工作台内）

- **展示**：说明「默认微信关注登录；也可在登录页切换手机号短信登录」。
- **手机号**：未绑定时展示「未绑定」+ 按钮「绑定手机号」；已绑定时展示脱敏手机号（如 134****9810）+ 按钮「更换手机号」。点击按钮打开登录弹窗并建议切到手机号 Tab，完成验证后更新绑定关系。
- **微信号**：已绑定展示「微信号已绑定」+ 可选「解除绑定」（若业务支持）；未绑定展示「未绑定」。
- **登录方式说明**：底部可简要说明当前支持的登录方式与绑定逻辑。

## 4. 字段规格表

| 字段显示名 | 字段键名 | 所在区域 | 类型 | 必填 | 长度/格式 | 取值来源 | 说明 |
|------------|----------|----------|------|------|-----------|----------|------|
| 微信头像 | avatar_url | 登录成功后展示 | string | — | URL | 微信接口 | 用于导航栏/工作台 |
| 微信昵称 | nickname | 登录成功后展示 | string | — | ≤64 | 微信接口 | 用于导航栏/工作台 |
| Token | token / access_token | 请求头 | string | — | JWT | 服务端生成 | 有效期 7 天 |
| 手机号 | phone | 账号设置/短信登录 | string | 短信登录必填 | 11 位 | 用户输入/后端校验 | 绑定后账号设置展示脱敏 |
| 验证码 | sms_code | 短信登录 | string | 是 | 4～6 位 | 短信下发 | 发送验证码后倒计时防重复 |

- 注册/登录过程由后端与微信开放平台对接，前端仅展示二维码与轮询/回调结果；手机号登录由后端对接短信服务，前端提交手机号+验证码。

---

## 5. 业务逻辑与状态流转

- **R-01**：未注册用户扫码并授权后，后端自动创建用户（拉取 openid、头像、昵称），并签发 JWT，与「已注册用户」同一套登录成功逻辑。
- **R-02**：Token 有效期 7 天；刷新页面或切换页面时，前端携带 Token 请求用户信息，失败（401）则清除本地 Token 并引导重新扫码。
- **R-03**：同一微信账号多次扫码登录，视为同一用户（openid 唯一）。

---

## 6. 异常与边界

- 网络异常：轮询或回调超时，提示「网络异常，请重试」或「请重新扫码」。
- 用户取消授权：微信端取消后，二维码可刷新再次扫码。
- 多端登录：是否允许多端同时登录由后端策略决定，PRD 不强制。

---

## 7. 依赖与待定项

- **依赖**：微信开放平台 Web 应用授权、后端生成二维码与回调验签；前端需提供回调页或轮询接口；手机号登录依赖短信服务与验证码校验接口。
- **已定**：支持手机号短信登录（登录弹窗内 Tab 切换）及账号设置页手机号绑定/更换、微信号绑定状态展示；解除微信号绑定为可选能力。
