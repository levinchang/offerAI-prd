# M7.1 用户列表

| 项目 | 说明 |
|------|------|
| **功能名称** | 用户列表与查询 |
| **对应 FeatureList** | 9.7.1 用户列表、9.7.2 渠道数据 |
| **对应 ER 实体** | 用户、会员权益 |
| **对应时序图** | 无 |

---

## 1. 需求背景与目标

- 运营需按注册时间、会员状态、UTM 来源筛选用户，查看用户基础信息、**手机号/邮箱（选填，用于后续营销）**、会员/消费概览，并可对用户进行**禁用**等操作。
- 目标：列表支持筛选与分页；可进入用户详情查看其订单、会员、已购资料摘要；支持**禁用用户**（禁用后不可登录前台）；用户可选填手机号、邮箱，存储在个人资料中，供后续营销使用。

---

## 2. 角色与入口

- **角色**：管理员。
- **入口**：左侧菜单「用户与反馈」→ Tab「用户列表」；右侧主内容区为筛选 + 表格；行内「详情」打开抽屉或跳转详情页。
- **登录态**：需已登录后台。

---

## 3. 页面结构与交互

- **布局**：左侧菜单 + 右侧主内容区。
- **筛选**：注册时间范围、会员状态（全部/校招会员/事业编会员/非会员）、UTM 来源（下拉或输入）、**账号状态**（全部/正常/已禁用）。
- **表格列**：用户ID、微信昵称、头像（小图）、**手机号**、**邮箱**、注册时间、UTM 来源、校招会员到期、事业编会员到期、累计消费（可选）、**账号状态**、操作（详情、**禁用/启用**）。
- **用户详情**（抽屉或子页）：基础信息（含手机号、邮箱）；最近订单列表（前 N 条）；已购资料列表（前 N 条）；会员信息与「会员管理」入口；**禁用/启用**操作（禁用后该用户不可登录前台，仅管理员可恢复启用）。
- **禁用/启用**：行内或详情内「禁用」→ 二次确认后将该用户标记为禁用，前台登录时拒绝；「启用」恢复为正常。当前登录用户不可禁用自己（若用户表与管理员表分离，此处指前台用户）。

---

## 4. 字段规格表

| 字段显示名 | 字段键名 | 区域 | 类型 | 必填 | 说明 |
|------------|----------|------|------|------|------|
| 用户ID | user_id | 列表/详情 | bigint | — | PK |
| 微信昵称 | nickname | 列表/详情 | string | — | 来自用户表 |
| 头像 | avatar_url | 列表/详情 | string | — | URL，列表可缩略 |
| **手机号** | **phone** | 列表/详情 | string | **否（选填）** | 用户个人资料选填，用于营销/触达 |
| **邮箱** | **email** | 列表/详情 | string | **否（选填）** | 用户个人资料选填，用于营销/触达 |
| 注册时间 | created_at | 列表/筛选 | datetime | — | — |
| UTM 来源 | utm_source | 列表/筛选 | string | — | 注册时记录 |
| 校招会员到期 | campus_expire_at | 列表 | date | — | 同 M6.2 逻辑 |
| 事业编会员到期 | civil_expire_at | 列表 | date | — | 同 M6.2 逻辑 |
| 累计消费 | total_paid | 列表 | decimal | — | 可选，已支付订单金额汇总 |
| **账号状态** | **status** | 列表/筛选/详情 | enum | — | **正常 / 已禁用**；禁用后不可登录前台 |

- **手机号、邮箱**：由用户在前台「个人资料」中选填；后台仅展示与筛选（若需），不在此编辑；用于后续短信/邮件营销等，需符合隐私与合规要求。

---

## 5. 业务逻辑与状态流转

- **R-01**：会员状态筛选可基于「当前是否有有效会员」判断（到期日≥今日）。
- **R-02**：累计消费仅统计订单状态=已支付的订单实付金额之和；退款是否扣减由实现决定（建议扣减）。
- **R-03**：**禁用用户**：将用户 status 置为禁用；前台校验登录态或登录时若为禁用则拒绝访问；仅管理员在后台可「启用」恢复。
- **R-04**：手机号、邮箱由前台用户中心/个人资料维护，后台只读；若后台需支持代填或修改，需单独权限与审计。

---

## 6. 异常与边界

- 无用户时列表空状态；详情中无订单/无已购资料时展示「暂无」。
- 禁用后用户已持有的会员/已购资料不自动清空，仅禁止登录与后续使用；是否限制已购内容访问由产品决定。

---

## 7. 依赖与待定项

- **依赖**：用户表（含 status、phone、email 等）、会员权益表、订单表、用户资料权限表；前台个人资料页提供手机号/邮箱选填。
- **待定**：渠道概览（9.7.2）是否在本页增加 Tab 或单独页展示各 utm_source 的注册数/付费数；营销使用手机号/邮箱的合规与授权由运营与法务约定。
