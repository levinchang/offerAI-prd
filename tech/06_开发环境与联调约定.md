# 06 开发环境与联调约定

本文档约定**环境变量、第三方配置预留、开发期沙箱与 Mock 策略**，便于本地与联调环境一致、上线前仅切换配置即可。

---

## 6.1 环境变量清单

项目根目录提供 `.env.example`（不提交真实密钥），下列变量在实现时按需读取。

### 6.1.1 数据库与缓存

| 变量名 | 说明 | 示例值（本地） |
|--------|------|----------------|
| `DATABASE_URL` | PostgreSQL 连接串 | `postgresql://user:pass@localhost:5432/offerai` |
| `REDIS_URL` | Redis 连接串 | `redis://localhost:6379` |

### 6.1.2 阿里云 OSS

| 变量名 | 说明 | 示例值 |
|--------|------|--------|
| `OSS_REGION` | 地域，如 oss-cn-hangzhou | 按实际 Bucket 地域 |
| `OSS_ACCESS_KEY_ID` | 访问密钥 ID | — |
| `OSS_ACCESS_KEY_SECRET` | 访问密钥 Secret | — |
| `OSS_BUCKET` | Bucket 名称（资料与简历可同桶不同前缀，或分桶） | 如 `offerai-files` |

- 建议目录：`docs/` 存面试资料 PDF，`resumes/` 存用户简历；权限设为私有，通过后端签名 URL 或服务端代理访问。

### 6.1.3 微信（预留，开发期可空或 Mock）

| 变量名 | 说明 | 备注 |
|--------|------|------|
| `WECHAT_APP_ID` | 开放平台 / 公众号 AppID | 登录用 |
| `WECHAT_APP_SECRET` | AppSecret | 登录用 |
| `WECHAT_PAY_MCH_ID` | 支付商户号 | 支付用 |
| `WECHAT_PAY_API_KEY` | 支付 API 密钥（V3 key） | 支付用 |
| `WECHAT_PAY_CERT_PATH` | 商户证书路径（可选，视接口要求） | 退款等需证书 |

- 开发期：不配置或留空；登录与支付走 Mock（见 6.3、6.4）。

### 6.1.4 支付宝（预留，开发期可空或 Mock）

| 变量名 | 说明 | 备注 |
|--------|------|------|
| `ALIPAY_APP_ID` | 应用 ID | — |
| `ALIPAY_PRIVATE_KEY` | 应用私钥（PKCS8） | — |
| `ALIPAY_PUBLIC_KEY` | 支付宝公钥 | 验签用 |
| `ALIPAY_GATEWAY` | 网关地址 | 沙箱：https://openapi-sandbox.dl.alipay.com/gateway.do |

- 开发期：不配置或使用沙箱环境变量；支付走 Mock 或沙箱。

### 6.1.5 短信（预留，开发期可 Mock）

| `SMS_SECRET` | — | — |

| `SMS_TEMPLATE_CODE_VERIFY` | 验证码模板 ID | — |

### 6.1.6 应用与安全

| 变量名 | 说明 | 示例值 |
|--------|------|--------|
| `NEXT_PUBLIC_APP_URL` | 前端/站点根 URL | `http://localhost:3000` |

## 6.2 开发期整体策略

- **目标**：在未开通正式微信开放平台、未签约支付与短信前，能完成**除真实第三方调用外的全部功能**开发与联调。
- **约定**：
  - **登录**：全程 Mock；见 6.3。
  - **支付**：全程沙箱或 Mock；见 6.4。
  - **短信**：Mock 固定验证码或内存/Redis 模拟；见 6.4。
- **上线前**：配置真实环境变量、切换网关与回调 URL、关闭 Mock 开关即可。

---

## 6.3 登录 Mock 策略

- **微信扫码登录**：
  - 若未配置 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`，或配置了 `MOCK_WECHAT_LOGIN=true`：
    - 前端展示「开发模式：点击模拟扫码」按钮；点击后调用后端 `POST /api/auth/wechat/mock`（仅开发环境可用），传入 mock 参数如 `openid=test_openid_001`、`nickname=测试用户`。
    - 后端在 Mock 模式下：不请求微信接口，直接按 openid 查/建用户，签发 JWT，返回与正常登录一致的结构。
  - 生产环境关闭 Mock 或移除 mock 接口。
- **手机号验证码登录**：
  - 若未配置短信或 `MOCK_SMS=true`：后端发送验证码时**不真正发短信**，而是将验证码写入 Redis（key 如 `sms:${phone}`，TTL 5 分钟）；可选在响应中**开发环境返回验证码**（如 `{ needVerify: true, devCode: "123456" }`），仅当 `NODE_ENV=development` 时返回，方便自测。
  - 校验验证码逻辑与生产一致：从 Redis 读并比对，通过则删 key。

---

## 6.4 支付 Mock / 沙箱策略

- **创建订单**：
  - 若未配置微信/支付宝支付密钥，或 `MOCK_PAYMENT=true`：
    - 后端仍写 `orders`（状态 pending），但**不调用**微信/支付宝统一下单；返回给前端的支付参数为 Mock 数据，例如 `{ mock: true, orderNo: "xxx", message: "开发模式：无需真实支付" }`。
    - 前端展示「开发模式：模拟支付成功」按钮，点击后调用 `POST /api/pay/mock/confirm`（仅开发环境），传入 `order_no`；后端将该订单更新为已支付、写支付流水、**按 04 文档正常发放权益**。
  - 这样**权益发放链路与生产一致**，仅支付渠道为 Mock。
- **沙箱**：若已申请微信/支付宝沙箱账号，可配置沙箱的 AppID、商户号、密钥等，创建订单时调沙箱统一下单，用户用沙箱钱包或扫码沙箱二维码完成支付，回调 URL 指向开发机或内网穿透地址；回调逻辑与生产相同（验签用沙箱公钥）。

## 6.5 本地环境建议

- **PostgreSQL**：Docker 运行，如 `docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=local postgres:17`；首次建库后执行迁移脚本（按 02 文档建表）。
- **Redis**：Docker 运行，如 `docker run -d -p 6379:6379 redis:7`。
- **阿里云 OSS**：本地开发可使用同一 Bucket、不同前缀（如 `dev/docs/`），或单独建开发 Bucket，避免与测试/生产混用。
- **.env.local**：从 `.env.example` 复制，填本地 DATABASE_URL、REDIS_URL、JWT_SECRET、OSS 等；微信/支付宝/短信留空并开启上述 Mock 开关即可。

---

## 6.6 上线前检查项（清单）

- [ ] 关闭或移除所有 Mock 接口（如 `/api/auth/wechat/mock`、`/api/pay/mock/confirm`），或通过环境变量严格限制仅开发环境可访问。
- [ ] 配置生产用 `WECHAT_*`、`ALIPAY_*`、`SMS_*`，并确认回调 URL 为生产域名。
- [ ] 支付回调验签使用**生产公钥/证书**，不再使用沙箱。
- [ ] `JWT_SECRET`、`ADMIN_JWT_SECRET` 使用强随机串，且不提交到仓库。
- [ ] OSS Bucket 权限与 CORS 按生产要求收紧；敏感文件（PDF、简历）不设公共读。
