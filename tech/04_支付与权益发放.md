# 04 支付与权益发放

本文档约定**创建订单 → 调起支付 → 异步回调 → 更新订单与发放权益**的流程、状态机、幂等与安全要点。流程与 `../时序图05_会员购买.mmd` 一致；资料订单与会员订单共用同一套支付通道，仅在「发放权益」环节按 `product_type` 分支。

---

## 4.1 支付流程总览

```
用户选择商品(SKU/资料) → 前端请求创建订单 → 后端校验并写入 orders(待支付)
    → 后端调微信/支付宝下单接口 → 返回支付参数(二维码URL/调起参数)
    → 前端展示二维码或调起支付 → 用户完成支付
    → 微信/支付宝 异步回调 后端 → 验签 → 幂等判断 → 更新订单+写支付流水+发放权益
    → 前端轮询订单状态或跳转结果页 → 展示支付成功与权益
```

- **会员订单**：`product_type=membership`，`sku_id` 必填；发放时根据 SKU 的 `type`（campus/civil/all）写/更新 `member_rights`。
- **资料订单**：`product_type=doc`，`doc_id` 必填；发放时写 `user_doc_access`。

---

## 4.2 创建订单（POST /api/orders）

### 4.2.1 入参

- `product_type`：`membership` | `doc`
- `product_id`：会员时为 `sku_id`，资料时为 `doc_id`（与下二选一语义一致即可）
- 可选：`promo_code`（优惠码）、`pay_channel`（wechat/alipay，用于后续下单渠道）

### 4.2.2 逻辑

1. **鉴权**：必须登录，取 `user_id`。
2. **校验商品**：  
   - 会员：查 `skus` 表，`id=product_id` 且 `status=published`；取 `list_price`、`promo_price`、`type`、`duration_days`。  
   - 资料：查 `docs` 表，`id=product_id` 且 `status=published`；取 `price`；可选校验用户是否已购（已购则提示勿重复下单）。
3. **优惠码**（若传）：查 `promo_templates` 与 `user_coupons`，校验适用类型、未过期、未超用；计算抵扣后实付金额。
4. **生成订单号**：全局唯一，如 `ORD` + 时间戳 + 短随机，或雪花 ID。
5. **写库**：插入 `orders`，`order_status=pending`，`pay_amount` 为实付；若使用优惠券则写 `user_coupon_id`。
6. **返回**：`order_no`、`pay_amount`、`pay_channel`；以及**支付参数**（由后端调微信/支付宝「统一下单」接口获得）：
   - PC：`code_url`（二维码链接）或 `qr_code` 图片 URL。
   - H5：`redirect_url` 或 `h5_url` 供前端跳转。

### 4.2.3 异常

- SKU/资料不存在或已下架 → 400。
- 已购资料重复下单 → 400，提示已拥有。
- 优惠码无效/已过期/已用尽 → 400，提示具体原因。

---

## 4.3 调起支付（后端调微信/支付宝）

- 后端在创建订单后**立即**调用微信/支付宝「统一下单」类接口，传入：商户订单号（即 `order_no`）、金额（元转分）、回调 URL、用户 openid（H5/小程序时）等。
- 将返回的 `code_url`、`prepay_id`、`redirect_url` 等放入创建订单接口的响应中，前端仅展示或跳转，不存敏感密钥。

---

## 4.4 支付回调（POST /api/pay/notify/wechat | /api/pay/notify/alipay）

### 4.4.1 职责

- **不校验用户 JWT**：回调由支付平台服务器调用，仅做**验签**与**订单维度**处理。
- 从回调 body 中解析：第三方交易号、商户订单号（即 `order_no`）、支付结果、金额（分转元）。

### 4.4.2 流程（建议在同一事务或可补偿的步骤内）

1. **验签**：使用微信/支付宝公钥与回调 body 验签，失败则记录日志并返回失败响应（以便渠道重试）。
2. **幂等**：用 `order_no` 查 `orders`；若 `order_status=paid`，视为已处理，直接返回成功，**不再重复发放权益**。
3. **校验金额**：回调中的实付金额与订单表 `pay_amount` 一致（允许分与元换算误差）。
4. **更新订单**：`order_status=paid`，`paid_at=now()`，`pay_channel` 若尚未写可在此写入。
5. **写支付流水**：插入 `payment_logs`，`transaction_id`、`amount`、`callback_status=success`、`paid_at`。
6. **发放权益**（见 4.6）。
7. **若使用优惠券**：更新 `user_coupons` 中对应记录为已使用，`use_order_id=当前订单id`。
8. 返回给渠道的 HTTP 200 及渠道要求的 success 报文，避免渠道重复回调。

### 4.4.3 失败与重试

- 若步骤 4～7 任一步失败（如 DB 异常），**不要**返回 success；渠道会按策略重试。
- 建议写日志（order_no、transaction_id、异常信息），便于对账与人工补发。

## 4.5 订单状态机

| 状态 | 含义 | 可流转至 |
|------|------|----------|
| pending | 待支付 | paid（支付成功）、closed（超时/取消） |
| paid | 已支付 | refunded（退款，若支持） |
| refunded | 已退款 | — |
| closed | 已关闭 | — |

- **超时关闭**：可选定时任务，将创建超过 N 分钟（如 30）且仍为 `pending` 的订单置为 `closed`；关闭后不再接受回调写入 `paid`（回调时若已是 closed，可记录日志并返回成功，避免渠道一直重试）。

## 4.6 权益发放细则

### 4.6.1 会员订单（product_type=membership）

- 根据 `orders.sku_id` 查 `skus`，得到 `type`（campus/civil/all）与 `duration_days`。
- **当前用户该类型的到期时间**：查 `member_rights` 表，`user_id=orders.user_id` 且 `member_type=type`，取 `expire_at` 最大的一条；若不存在或已过期，则基准时间为 `now()`，否则为 `max(expire_at)`。
- **新到期时间** = 基准时间 + `duration_days` 天。
- **写入**：插入一条 `member_rights`，`user_id`、`order_id`、`member_type`、`start_at`（可取基准时间）、`expire_at`（新到期时间）、`status=active`。  
  - 若希望「同一类型只保留一条」且用「最大到期时间」展示，可改为：查已有记录并 UPDATE 该记录的 `expire_at` 为 `GREATEST(expire_at, 新到期时间)`，或先插入再在查询层按 user_id+member_type 取 max(expire_at)。以产品约定为准。
- **双会员（type=all）**：对 `campus` 与 `civil` 各做一次上述逻辑（两条记录或两次更新）。

### 4.6.2 资料订单（product_type=doc）

- 根据 `orders.doc_id` 与 `orders.user_id`，插入 `user_doc_access`（`user_id`、`doc_id`、`order_id`、`unlocked_at=now()`）。
- **唯一约束**：`(user_id, doc_id)`，若已存在则跳过插入（防重复发放），并仍将订单置为已支付、流水照写。
- 可选：更新 `docs.sale_count` +1（可异步）。

## 4.7 安全与对账要点

- **回调验签**：必须使用官方 SDK 或按文档用公钥验签，防止伪造回调。
- **金额校验**：回调金额与订单 `pay_amount` 一致再发权益。
- **幂等**：以 `order_no` + `order_status=paid` 为幂等条件，同一订单只发一次权益。
- **对账**：定期用 `payment_logs` 与支付渠道后台对账（交易号、金额、状态）；发现不一致时以渠道为准，缺单补单、多单排查。

---

## 4.8 前端配合

- 创建订单后展示二维码或跳转 H5；用户支付完成后，前端可**轮询** `GET /api/orders/:orderNo`，当 `order_status=paid` 时跳转支付成功页并展示权益（如校招/事业编到期时间、资料已解锁）。
- 支付成功页可提供「查看权益」「去使用」等入口，与 [03_接口与鉴权](./03_接口与鉴权.md) 中「用户信息/我的资料」接口配合。
