# 02 数据模型与存储

本文档与 `../offerAI_ER图.mmd` 对齐，给出可落库的**表名、字段、类型、索引与约束**。库表命名采用小写 + 下划线（snake_case）。

- **目标数据库**：PostgreSQL（当前最新稳定版，见 [01_技术栈与架构](./01_技术栈与架构.md)）。以下类型按 PG 书写（如 `BIGINT`、`SERIAL`、`VARCHAR`、`TEXT`、`DECIMAL`、`JSONB` 等）；若后续改用 MySQL，需做少量类型与自增语法映射。

## 2.3 索引建议

| 表 | 索引 | 用途 |
|------|------|------|
| users | UK(openid), UK(phone), idx(created_at) | 登录、按时间查 |
| orders | UK(order_no), idx(user_id, created_at), idx(order_status) | 订单号查、用户订单列表、回调查待支付 |
| payment_logs | UK(transaction_id), idx(order_id) | 幂等、按订单查流水 |
| member_rights | idx(user_id, member_type, status), idx(expire_at) | 查用户当前权益、到期提醒 |
| campus_jobs | idx(publish_status, lifecycle), idx(updated_at), idx(industry), idx(recruit_type) | 列表筛选、排序 |
| civil_posts | idx(publish_status, lifecycle), idx(updated_at), idx(province, post_type) | 同上 |
| docs | idx(status), idx(industry), idx(updated_at) | 资料列表筛选 |
| user_doc_access | UK(user_id, doc_id), idx(user_id) | 判是否已购、我的资料列表 |
| apply_records | idx(user_id, source_type), idx(user_id, stage), idx(group_id) | 看板、列表、分组筛选 |
| favorites | UK(user_id, target_type, target_id), idx(user_id) | 去重、收藏列表 |
| dict_items | idx(field_key, status), idx(field_key, sort_order) | 按字段拉枚举 |

## 2.4 数据一致性与约束

- **外键**：建议在应用层保证一致性；若数据库支持且团队规范允许，可为关键表加 FK。
- **唯一约束**：order_no、transaction_id、user_id+doc_id、user_id+target_type+target_id 等已在上文或索引中体现。
- **删除策略**：岗位/资料采用 `lifecycle` 或 `status` 软删；订单、支付流水、权益记录不物理删除；用户可软删或脱敏后保留。
- **金额**：订单与支付相关金额统一 decimal(10,2)，单位元。
