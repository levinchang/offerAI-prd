# 03 接口与鉴权

本文档约定 Next.js 作为后端时的 **API 规范、鉴权方式、接口清单**。接口以 Next.js App Router 的 **Route Handlers**（或 Pages 的 API Routes）实现，路径前缀建议 `/api`。

---

## 3.1 API 规范

### 3.1.1 路径与方法

- **前缀**：`/api`；管理后台可用 `/api/admin` 区分。
- **风格**：REST 风格；资源名复数、小写、连字符可选。  
  示例：`GET /api/skus`、`GET /api/campus-jobs`、`POST /api/orders`、`GET /api/users/me`。
- **方法**：  
  - `GET` 查询；`POST` 创建或复杂查询（如列表带多条件）；`PUT`/`PATCH` 更新；`DELETE` 删除（若提供）。

### 3.1.2 统一响应结构

**成功（业务成功）**

```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

**失败（业务失败，HTTP 200 或 4xx 视习惯）**

```json
{
  "code": 40001,
  "message": "未登录或登录已过期",
  "data": null
}
```

- 建议：**鉴权失败**（未登录、无权限）用 **HTTP 401/403**，body 仍用上述结构；**参数校验失败** 用 400；**服务异常** 用 500。

### 3.1.3 错误码约定

| 码段 | 含义 | 示例 |
|------|------|------|
| 0 | 成功 |  |
| 40001 | 未登录 / Token 无效 |  |
| 40003 | 无权限（如非会员访问会员能力） |  |
| 40004 | 资源不存在 |  |
| 40010～40099 | 业务参数错误 | 如 40010 优惠码无效 |
| 50000 | 服务内部错误 |  |

### 3.1.4 分页

- 请求：`page`（从 1）、`page_size`（默认 20，最大可限 100）。  
  或 `cursor` + `page_size`（游标分页，适合大列表）。
- 响应：`data.list`、`data.total`（总条数）；游标时 `data.next_cursor`。

## 3.2 鉴权策略

### 3.2.1 C 端用户（前台）

- **方式**：**JWT**，放在请求头 `Authorization: Bearer <token>`；或 Cookie（HttpOnly，SameSite）。  
  Next.js 中可在 Route Handler 内或中间件中解析 JWT，将 `user_id`、`openid`、`phone` 等注入请求上下文。
- **签发**：登录成功（微信扫码 / 手机号验证码）后签发；payload 建议包含：`sub`(user_id)、`openid`（可选）、`phone`（可选）、`exp`、`iat`。
- **有效期**：如 7 天；可选 refresh token 或滑动过期，本期可仅 access token。
- **校验**：  
  - 需要登录的接口：无有效 Token → 401 + code 40001。  
  - 需要校招会员：先校验登录，再查 `member_rights` 中该用户 campus 类型是否 `expire_at > now()` → 否则 403 + code 40003。  
  - 事业编会员、资料已购同理。

### 3.2.2 管理后台（Admin）

- **方式**：与 C 端隔离时，管理员使用 **单独登录接口**（如 `POST /api/admin/auth/login`），校验 `admins` 表，签发 **Admin JWT**（或 Session），请求头同上。
- **路径**：所有后台接口统一前缀 `/api/admin`，中间件仅校验 Admin Token；C 端 Token 访问 `/api/admin/*` 一律 403。

### 3.2.3 支付回调

- **不校验用户 JWT**：回调由微信/支付宝服务器调用，通过 **签名验签** 与 **订单号/商户单号** 确定合法性；回调 handler 内只做验签、查单、更新状态、发权益。

## 3.4 鉴权与权限在实现中的落点

- **Next.js 中间件**：对 `/api/*` 做 Token 解析（除白名单：登录、回调、字典公开接口），将 `user_id` 写入 header 或 context，下游 Route Handler 直接读。
- **业务层**：需要「校招会员」的接口（如列表返链接、投递记录）：在 handler 内查 `member_rights` 中 campus 是否有效；需要「事业编会员」「资料已购」同理。
- **前台请求**：前端在 axios/fetch 拦截器中附加 `Authorization`，收到 401/403 时跳转登录或套餐页。

## 3.5 核心接口请求/响应示例（契约）

以下为部分核心接口的请求/响应形状，便于前后端首轮对齐；其余接口按 02 表结构与业务补齐。

### POST /api/orders（创建订单）

**请求体**

```json
{
  "product_type": "membership",
  "product_id": 1,
  "pay_channel": "wechat",
  "promo_code": ""
}
```

- `product_type`：`membership` | `doc`
- `product_id`：会员时为 `sku_id`，资料时为 `doc_id`
- `pay_channel`：`wechat` | `alipay`
- `promo_code`：可选

**成功响应（200）**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "order_no": "ORD20250306123456",
    "pay_amount": 19.9,
    "pay_channel": "wechat",
    "code_url": "weixin://wxpay/...",
    "expires_at": "2025-03-06T12:40:00Z"
  }
}
```

- 开发期 Mock 时 `code_url` 可为空或占位，`data.mock` 为 true 时前端展示「模拟支付成功」按钮。

### GET /api/campus-jobs（校招列表）

**Query**

| 参数 | 类型 | 说明 |
|------|------|------|
| page | number | 从 1 |
| page_size | number | 默认 20 |
| recruit_type | string | 招聘类型，可选 |
| industry | string | 所属行业，可选 |
| city | string | 城市，可选 |
| keyword | string | 职位/公司模糊，可选 |

**成功响应（200）**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": 1,
        "company_name": "某公司",
        "job_title": "产品经理",
        "city": "北京",
        "recruit_type": "26届春招",
        "industry": "互联网",
        "apply_end_date": "2025-04-30",
        "apply_url": "https://...",
        "original_url": "https://..."
      }
    ],
    "total": 100
  }
}
```

- 未登录或非校招会员时，`apply_url`、`original_url` 不返回或为 `null`；前端据此展示「登录后可查看」「开通会员解锁」。

### GET /api/users/me（当前用户与权益）

**成功响应（200）**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "user_id": 1,
    "nickname": "用户昵称",
    "avatar_url": "https://...",
    "phone": "138****0000",
    "phone_bound": true,
    "campus_expire_at": "2026-03-06T00:00:00Z",
    "civil_expire_at": null
  }
}
```

- 未开通的会员类型对应字段为 `null`；前端据此展示「未开通」与「立即开通」。
