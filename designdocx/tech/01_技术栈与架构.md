# 01 技术栈与架构

## 1.1 技术栈选型

| 层级 | 选型 | 说明 |
|------|------|------|
| **后端** | **Next.js**（App Router + Route Handlers / API Routes） | 前后端一体；接口以 Route Handlers 或 API Routes 实现，与前端同仓库、同部署。 |
| **前端（C 端）** | Next.js 前端（React） | 页面与组件；与后端共享项目，通过内部请求或同源 API 调用。 |
| **前端（管理后台）** | Next.js 或独立 SPA | 可与 C 端共用 Next 项目（不同路由前缀，如 `/admin`），或单独仓库，按团队习惯定。 |
| **数据库** | **PostgreSQL**（当前最新稳定版，如 16.x / 17.x） | 主库，存用户、订单、会员、信息表、资料、投递、字典等；建表与迁移按 [02_数据模型与存储](./02_数据模型与存储.md)。 |
| **缓存** | **Redis**（建议 7.x） | 见下「Redis 使用建议」。 |
| **文件存储** | **阿里云 OSS** | 面试资料 PDF、用户上传简历；Bucket 与权限由后端控制，不直连前端；上传/下载通过后端签名 URL 或代理。 |
| **支付** | 微信支付、支付宝 | 服务端下单与回调验签在 Next.js API 内完成；**开发期使用沙箱/Mock**，见 [06_开发环境与联调约定](./06_开发环境与联调约定.md)。 |

### Redis 使用建议

- **建议使用**，用于以下场景（按优先级）：
  1. **短信验证码**：存储「手机号 → 验证码、过期时间」；发送前做**限流**（同一手机 1 分钟内不重复发）；校验后即删或标记已用，避免重复使用。
  2. **字典 / SKU 缓存**：`dict_items`、在售 SKU 列表读多写少，可缓存 5～10 分钟，减轻 DB；字典/价格变更时删缓存。
  3. **登出 / 封禁**（可选）：登出后将 token 放入黑名单（TTL 等于 token 剩余有效期）；校验 token 时先查黑名单。若首期不做「立即踢下线」，可暂不实现，仅依赖 JWT 短期有效。
- **结论**：首期**必用** Redis 做验证码存储与限流；字典/SKU 缓存建议上；黑名单可二期。本地开发用 Docker 起 Redis 即可。

## 1.2 系统分层（逻辑视图）

```
┌─────────────────────────────────────────────────────────────┐
│  用户 / 管理员                                                │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  Next.js 应用                                                │
│  ├── 前端（C 端页面 + 管理后台页面）                           │
│  └── API 层（Route Handlers / API Routes）                   │
│        ├── 鉴权中间件 / 统一校验                               │
│        ├── 账户、会员、订单、支付、信息表、资料、投递、字典…     │
│        └── 支付回调、飞书 Webhook（如用）等独立入口             │
└─────────────────────────────────────────────────────────────┘
                              │
         ┌────────────────────┼────────────────────┐
         ▼                    ▼                    ▼
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│  PostgreSQL     │  │  Redis           │  │  阿里云 OSS      │
│  (主库)         │  │  验证码/缓存     │  │  资料 PDF/简历   │
└─────────────────┘  └─────────────────┘  └─────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────────┐
│  第三方：微信登录/支付、支付宝、短信、飞书 API                 │
└─────────────────────────────────────────────────────────────┘
```

- 不单独画「网关」：若部署在 Vercel/自建 Node，可直接用 Next.js 作为唯一入口；若有 Nginx/网关，可在部署阶段再补。

## 1.3 模块边界（按领域划分）

| 模块 | 职责 | 主要 API 与数据 |
|------|------|------------------|
| **账户与鉴权** | 登录（微信/手机号）、Token 签发与校验、绑定信息 | 用户表、登录态；JWT 或 Session |
| **会员与订单** | SKU、下单、支付参数、回调、权益发放 | 订单、支付流水、会员权益、SKU |
| **校招信息表** | 列表/详情、筛选、权限控制（链接按会员） | 校招岗位表；飞书同步写入 |
| **事业编信息表** | 同上，事业编维度 | 事业编岗位表；飞书同步写入 |
| **面试资料** | 资料 CRUD、预览、购买、下载（水印） | 面试资料表、用户资料权限 |
| **投递与工作台** | 投递记录、收藏、分组、简历库、账号设置 | 投递记录、收藏、分组、简历 |
| **字典与配置** | 校招/事业编/资料字典（行业、岗位等） | 字典表 |
| **后台管理** | 订单/会员/用户/资料/字典等管理、飞书同步 | 复用上述表；管理员鉴权 |

数据模型与接口设计将按上述模块组织；支付回调与权益发放归属「会员与订单」模块。
