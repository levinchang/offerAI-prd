# 05 业务模块实现要点

本文档按**业务模块**列出实现时的关键点、与其它模块的衔接、以及易遗漏的边界。表结构与接口以 [02_数据模型与存储](./02_数据模型与存储.md)、[03_接口与鉴权](./03_接口与鉴权.md) 为准。

---

## 5.1 账户与登录模块

### 5.1.1 微信扫码登录

- **流程**：前端拉取微信登录二维码（或后端生成 ticket 换二维码）；用户扫码后在微信内授权；微信重定向到回调地址并带 `code`；后端用 `code` 换 `openid`/`unionid`，查 `users` 表，无则插入新用户，有则更新昵称/头像（可选）；签发 JWT，返回前端。
- **要点**：openid 唯一，同一微信即同一用户；JWT payload 建议含 `sub=user_id`、`openid`（可选）；回调 URL 需在微信开放平台配置。

### 5.1.2 手机号验证码登录

- **流程**：前端提交手机号+验证码；后端校验验证码（与发送时一致、未过期）；查 `users` 表（按 phone），无则创建用户；签发 JWT。
- **要点**：验证码存储（Redis 或 DB）、过期时间（如 5 分钟）、发送频率限制（同一手机号 1 分钟 1 条）；验证码仅校验一次即失效。

### 5.1.3 绑定/更换手机号

- **入口**：工作台-账号设置；需已登录（微信已登录）。
- **逻辑**：发送验证码 → 用户提交新手机号+验证码；校验通过后更新 `users.phone`；若原已绑定可先校验旧手机号或仅验证码（产品定）。

### 5.1.4 与会员/权益的衔接

- `GET /api/users/me` 需聚合：用户基本信息、手机/微信绑定态、**校招/事业编会员到期时间**（从 `member_rights` 按 user_id 取 campus/civil 类型下 expire_at 最大且 status=active）。前端据此展示「已开通」「到期日」或「未开通」。

## 5.2 校招信息表模块

### 5.2.1 数据来源与优先级

- 数据来自**飞书同步**与**后台人工维护**；同一条以 `source_key` 或业务主键去重，飞书同步时若存在则更新，并遵守「手动锁定」规则（见 ER：`manual_lock` 为 true 时飞书不覆盖）。

### 5.2.2 列表与详情接口

- **列表**：仅返回 `publish_status=published` 且 `lifecycle` 非 deleted；筛选条件（招聘类型、行业、城市、关键词、网申截止等）对应到表字段与索引（见 02）；分页用 `page`/`page_size` 或 cursor。
- **权限**：未登录或非校招会员时，**不返回** `apply_url`、`original_url`，或返回占位；校招会员返回真实链接。可在查询层根据「当前用户是否校招会员」决定 SELECT 是否包含这两列，或查后做脱敏。

### 5.2.3 收藏与投递

- **收藏**：`favorites` 表，`target_type=campus`，`target_id=campus_job_id`；唯一约束 (user_id, target_type, target_id)；取消收藏即删除记录。
- **投递记录**：用户点击「标记投递」或选择阶段时，写 `apply_records`，`source_type=campus`，`campus_job_id` 必填，`stage` 按产品枚举；阶段变更可写 `apply_stage_logs`。需**校招会员**才允许写入/更新投递记录。

### 5.2.4 与工作台衔接

- 工作台「收藏职位-校招」：`GET /api/favorites/campus`，返回当前用户校招收藏列表（可连表 campus_jobs 带出标题、公司等）；「投递进度」看板数据来自 `apply_records`，按 `stage` 分组或列表，需带出来源（campus/civil）与跳转用的 job_id/post_id。

## 5.3 事业编信息表模块

### 5.3.1 与校招的差异

- 表为 `civil_posts`；筛选维度为省份/区域、类型、报名截止、学历/年龄等；权限控制为**事业编会员**才返回 `original_url`（报名/原文链接）。
- 列表与详情、收藏、投递记录的实现思路与校招一致：列表/详情按权限脱敏链接；收藏用 `favorites`（target_type=civil）；投递用 `apply_records`（source_type=civil，civil_post_id）。

### 5.3.2 事业编阶段枚举

- 投递阶段与校招可统一一套（如已投递、笔试、一面、二面、OC、已拒）或单独枚举（已报名、笔试、面试、录用、未过）；与 PRD/F6 一致，在 `apply_records.stage` 上使用同一套或做映射。

## 5.4 面试资料模块

### 5.4.1 资料列表与筛选

- **列表**：仅 `status=published`；筛选条件：行业（对应 `docs.industry`，来自字典 `doc_industry`）、岗位（`docs.job_type`，多选可存 JSON 或逗号分隔，筛选时 LIKE/JSON 包含）、关键词（标题/简介模糊）。前台「资料商城」的行业/岗位筛选项来自字典接口 `GET /api/dict/doc_industry`、`GET /api/dict/doc_position`（见 03）。

### 5.4.2 预览与权限

- **预览前 N 页**：根据 `docs.preview_pages` 与 `docs.file_key`，从 OSS 取前 N 页内容（或预生成的预览资源 URL）；未购用户仅能访问预览内容接口，不返回全文。
- **已购判断**：查 `user_doc_access` 是否存在 (user_id, doc_id)；已购可返回全文或按页返回、记录阅读位置（可选）。

### 5.4.3 购买与下载

- 购买走**统一下单**（product_type=doc，product_id=doc_id），支付成功后按 [04_支付与权益发放](./04_支付与权益发放.md) 写 `user_doc_access`。
- **下载**：已购用户请求 `GET /api/docs/:id/download`；后端用原始 PDF（OSS）+ 用户标识（user_id/手机号等）+ 订单号生成**带水印 PDF**（可实时生成或缓存），返回临时 URL 或流；未购返回 403。

### 5.4.4 后台与字典

- 后台资料管理：行业、岗位从**资料字典**（dict_fields 中 doc_industry、doc_position）拉取，编辑时下拉/多选；保存时 `docs.industry` 存 code 或 label，`docs.job_type` 存多选值（JSON 或逗号分隔）。与前台筛选一致。

## 5.5 投递看板与工作台模块

### 5.5.1 投递记录 CRUD

- **列表/看板**：按 `user_id` 查 `apply_records`；看板视图按 `stage` 分组；列表视图支持排序、按来源（campus/civil）、分组筛选。需**会员**（校招或事业编任一即可使用看板，PRD 约定）。
- **新增**：支持从校招/事业编详情页「标记投递」带入岗位信息；或工作台内「手动新增」：source_type=manual，company_name、job_title 必填。
- **更新**：阶段变更、备注、关联简历、所属分组；阶段变更时写 `apply_stage_logs`。
- **删除**：软删或物理删除按产品定；若软删，列表/看板需过滤已删除。

### 5.5.2 分组与收藏

- **分组**：`user_groups` 表，仅当前用户可见；投递记录上的 `group_id` 关联到分组；列表筛选「按分组」即 where group_id=?。
- **收藏**：校招/事业编收藏列表已见 5.2、5.3；工作台「收藏职位」两个 Tab 分别调 `/api/favorites/campus`、`/api/favorites/civil`，返回带岗位/公告摘要的列表，行内「查看详情」跳转对应详情页（用 target_id）。

### 5.5.3 简历库

- 上传：文件落 OSS，写 `resumes`（user_id、name、file_key、file_format）；限制格式与大小、单用户数量上限（如 5）。
- 投递记录关联简历：`apply_records.resume_id` 可选更新；简历删除后，关联该简历的投递记录可展示「已删除」或清空 resume_id。

### 5.5.4 账号设置

- 展示与绑定手机号、微信绑定态（见 5.1）；无单独表，读 `users` 即可。

## 5.6 会员与订单（后台）

- **订单列表**：按时间、用户、商品类型、订单状态筛选；详情含支付流水（payment_logs）。
- **会员列表**：按用户聚合，展示校招/事业编到期时间、已购资料数；到期时间从 `member_rights` 按 user_id+member_type 取 max(expire_at)。
- **延长会员**：写 `member_rights` 新记录或更新已有记录的 expire_at（业务规则：在原到期基础上加天数）；记录操作人、原因（可选）。
- **SKU 配置**：CRUD `skus` 表；前台套餐页仅展示 show_in_front=1 且 status=published 的 SKU。

---

## 5.7 字典与配置模块

### 5.7.1 字典字段划分

- **校招**：recruit_type、industry（所属行业）等，供校招岗位编辑与筛选。
- **事业编**：civil_type（事业单位/国企/银行等），供事业编岗位与筛选。
- **资料**：doc_industry、doc_position，供面试资料后台编辑与前台资料商城筛选。

### 5.7.2 接口与缓存

- `GET /api/dict/:fieldKey`：返回该 field_key 下 status=active 的 dict_items，按 sort_order；可对结果做短期缓存（如 Redis 5 分钟），字典项变更时失效。
- 后台字典管理：对 dict_fields、dict_items 的增删改；与 M8 PRD 一致。

---

## 5.8 飞书同步（可选实现顺序）

- 配置表 `feishu_sync_configs`；任务表 `sync_tasks`。同步任务读取飞书表格，按 source_key 去重，写入或更新 campus_jobs/civil_posts；若存在 manual_lock 则不覆盖。实现时可先做「手动触发」接口，再做定时任务。

---

以上各模块与 [03_接口与鉴权](./03_接口与鉴权.md) 中的接口一一对应；实现时以 02 表结构为准，权限判断统一依赖「当前 user_id + member_rights / user_doc_access」。
