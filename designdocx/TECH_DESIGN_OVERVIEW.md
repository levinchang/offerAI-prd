# Offer信息站（OfferAI）技术设计总览

> 目的：在 PRD 与 ER/时序图基础上，梳理一份**面向开发的技术设计清单**，作为各子系统技术方案的目录与检查表。  
> **细化文档已归入 [tech/](./tech/) 目录**，本文作为总索引。

## 1. 技术栈与整体架构

- **1.1 技术栈选型**（详见 [tech/01_技术栈与架构.md](./tech/01_技术栈与架构.md)）
  - **后端**：Next.js（App Router + Route Handlers / API Routes）
  - 前端（C 端 Web / 工作台）：Next.js 前端（React）
  - 前端（管理后台）：Next.js 同项目或独立 SPA
  - **数据库**：PostgreSQL（最新稳定版）
  - **缓存**：Redis（验证码、限流、字典/SKU 缓存；登出黑名单可选）
  - **文件存储**：阿里云 OSS（面试资料 PDF、用户简历）
  - **支付**：微信支付、支付宝；**开发期使用沙箱/Mock**（见 [tech/06_开发环境与联调约定.md](./tech/06_开发环境与联调约定.md)）
  - **微信/支付宝/短信**：配置项预留，后续由产品/运营提供；开发期登录与支付全程 Mock
- **1.2 系统架构图**
  - 前台 / 后台 / 网关 / 业务服务 / 数据库 / 第三方组件的调用关系
  - 支付回调与飞书同步等异步流程在架构中的位置
- **1.3 模块边界与部署单元（先不细化部署，仅划清服务/模块）**
  - 账户与鉴权模块
  - 会员与订单/支付模块
  - 校招信息表模块
  - 事业编信息表模块
  - 面试资料模块
  - 投递与工作台模块
  - 字典与配置模块

## 6. 前端实现方案（简要）

- **6.1 路由与页面结构**
  - C 端页面：首页、校招表、事业编表、面试资料、工作台、套餐/收银台、支付结果
  - 管理后台页面：飞书同步、校招/事业编列表、面试资料、订单、会员、用户、字典管理
- **6.2 状态管理与请求封装**
  - 全局状态：当前用户、会员类型与到期时间、登录态
  - HTTP 请求封装、错误处理、未登录/未会员时跳转或弹窗策略
- **6.3 组件复用与权限展示**
  - 列表筛选组件、分页组件、权限按钮显示/禁用逻辑
